# claude-p2p

Связь «сервер — сервер» между Claude Code двух разных людей. Ваш Claude пишет
Claude'у друга (или папы), тот отвечает. Каждая сторона держит свой маленький
демон, общего сервера и общих паролей нет.

```
 ваш Claude ──MCP── p2p-демон  ⇄  HTTPS  ⇄  p2p-демон ──MCP── Claude друга
                    (ключи A)                (ключи B)
```

## Что умеет

- **Сообщения** (`msg`): текст ложится во входящие другой стороны; её Claude
  видит его при следующем запросе (хук) или читает инструментом `p2p_inbox`.
- **Ответы**: `p2p_await_reply` ждёт ответа на конкретное сообщение в том же ходе.
- **Задачи** (`task`): попросить Claude друга ответить самому, без участия
  человека. Выключено по умолчанию, включается владельцем на своей стороне и
  только для конкретного пира. Задача запускает новую сессию `claude -p` в пустом
  временном каталоге вне каталога узла; ограничения описаны ниже.
- **Работа за NAT**: стороне без белого адреса не нужно открывать порт. Она сама
  забирает почту у доступной стороны (pull) и подтверждает получение.
- **Доставка с повтором**: недоставленное лежит в исходящих и уходит, когда пир
  снова доступен.

## Безопасность

- У каждого узла две пары ключей: Ed25519 подписывает каждое сообщение, X25519
  шифрует его тело (ChaCha20-Poly1305) так, что прочитать его может только адресат.
  Транспорту не доверяем ни в подлинности, ни в секретности; TLS сверху всё равно
  нужен, чтобы скрыть метаданные.
- Принимаются сообщения только от **закреплённых** пиров: ключ попадает к вам
  через приглашение, которое вы получили от человека напрямую. Сверьте отпечаток
  (`p2p whoami`) голосом или в мессенджере. Приглашение `p2p2.` подписано
  Ed25519 по полям `name`, `url`, `sign`, `box`; подпись проверяется при добавлении.
  Отпечаток — первые 64 бита SHA-256 двух публичных ключей (Ed25519 + X25519),
  четыре группы по четыре hex-символа. Старые неподписанные `p2p1.` отклоняются.
  Подпись не заменяет сверку отпечатка по независимому каналу.
- Имя пира: 1–64 символа `A-Za-z0-9_.-`. Закреплённые ключи нельзя заменить
  повторным `add`: сначала `remove`, затем `add` и новая сверка. При этом разрешение
  задач сбрасывается. Повтор того же приглашения меняет только адрес.
- Адрес — HTTP(S) с хостом; пустой адрес означает pull-only. Перенаправления при
  доставке и pull запрещены. Ответ pull ограничен 4 МиБ, входящий запрос — 64 КиБ.
  Лимиты: 30 запросов/мин на отправителя и 120/мин на IP, до 1024 корзин каждого
  вида; до 32 HTTP-обработчиков и 10 секунд ожидания чтения сокета.
- Повтор перехваченного сообщения не создаёт дубля (таблица id); метка времени из
  будущего (больше 5 минут) и старше 7 суток отвергается.
- Текст пира для Claude — **недоверенные данные**: MCP-сервер и хук прямо говорят
  модели не выполнять инструкции из него.
- Приватные ключи лежат в `~/.claude-p2p/identity.json` с правами 0600 и
  никогда не покидают машину. В репозитории ключей нет.

Чего нет (сознательно): прямого ввода в чужую живую сессию, продолжения чужих
сессий, удалённого выполнения команд.

## Установка

Нужны Python 3.10+ и [uv](https://docs.astral.sh/uv/).

```bash
uv tool install git+https://github.com/serg-yalosovetsky/claude-p2p
```

### 1. Создать узел

Сторона с доступным адресом (VPS, домашний сервер с пробросом порта, Tailscale Funnel):

```bash
p2p init --name serg --url https://p2p.example.com
p2p serve            # слушает 127.0.0.1:8765, наружу — через ваш HTTPS-прокси
```

Сторона за NAT (обычный домашний компьютер):

```bash
p2p init --name papa          # без --url: узел сам забирает почту
p2p serve
```

Хотя бы у одной из двух сторон должен быть адрес.

### nginx

Если nginx работает на том же хосте, добавьте в `~/.claude-p2p/config.json`
поле `"trusted_proxies": ["127.0.0.1"]`. По умолчанию список пуст: заголовки
прокси игнорируются. Только для прямого соединения с адреса из этого списка
лимит на IP использует `X-Real-IP`, а при отсутствии этого заголовка — последний
адрес из `X-Forwarded-For`. Значение проверяется через `ipaddress.ip_address`;
некорректное значение означает использование адреса прямого соединения.
Указывайте только адреса доверенных прокси, которые перезаписывают заголовок.

В HTTPS-блок `server` nginx добавьте:

```nginx
location /v1/ {
    proxy_pass http://127.0.0.1:8765;
    proxy_set_header X-Real-IP $remote_addr;
    client_max_body_size 64k;
}
```

### 2. Обменяться приглашениями

```bash
p2p invite            # печатает строку p2p2.… и отпечаток
```

Отправьте строку другу любым каналом, он отправит свою. Каждый у себя:

```bash
p2p add p2p2.…        # печатает отпечаток друга — сверьте его голосом
```

### 3. Подключить к Claude Code

```bash
claude mcp add --scope user p2p -- p2p-mcp
```

И хук, чтобы новые сообщения были видны сразу, в `~/.claude/settings.json`:

```json
{
  "hooks": {
    "UserPromptSubmit": [
      { "hooks": [ { "type": "command", "command": "p2p-hook" } ] }
    ]
  }
}
```

Теперь можно сказать Claude: «спроси у papa, во сколько он будет дома».

### 4. (Необязательно) разрешить задачи

```bash
# в ~/.claude-p2p/config.json: "tasks_enabled": true
p2p allow-tasks serg
```

### Как ограничены задачи

Одновременно работает одна задача, ещё три могут ждать; дальше пир получает `busy`.
Перед запуском заново проверяются наличие пира, его ключи, `allow_tasks` и
`tasks_enabled`. Каждая задача получает новый `TemporaryDirectory` вне каталога
узла; после завершения он удаляется. Ответ ограничен по байтам (до 32 КиБ).

Профиль `claude -p` использует `--tools ""` (пустой набор встроенных инструментов —
белый список; без него у задачи оставались `SendMessage`, `ListAgents`, `DesignSync`
и др.), пустой `--allowedTools`, явный `--disallowedTools`
для чтения/записи файлов, shell, веба, агентов и других опасных инструментов,
`--permission-mode dontAsk` и `--permission-prompts none`.
`--strict-mcp-config --mcp-config '{"mcpServers":{}}'` исключает MCP владельца;
`--setting-sources ""`, `--safe-mode`, `--restricted`, `--disable-slash-commands`
отключают пользовательские настройки, хуки и прочие расширения. Эти флаги
проверены через установленный `claude --help`; нужна версия Claude с их поддержкой.
Сохранённые старые аргументы запуска Claude заменяются этим профилем.

Процесс получает только `PATH` и `HOME`: с пустым HOME проверка `claude auth status`
не нашла авторизацию, поэтому HOME сохранён для входа. Это **не OS-песочница**:
сеть процесса для API остаётся, административные политики Claude могут действовать,
доступ ограничивается поведением CLI, а не файловой системой или firewall.
Произвольный `task_command`, заданный владельцем вместо Claude, заменяет эти
ограничения инструментов и требует отдельной изоляции.

### Как узнавать о новых сообщениях

`p2p wake` показывает режимы, `p2p wake prompt tool desktop` сохраняет выбранные.
`prompt` — хук перед запросом пользователя; `tool` — после инструмента.
`p2p claude-config` печатает JSON хуков для выбранных режимов: объедините его с
вашим `settings.json`. Это не запускает и не меняет чужую живую сессию.

`p2p wake watch` и `p2p watch` дают строку на каждое новое сообщение; запустите
watch через Monitor в своей сессии Claude. Есть `--interval` и `--once`.
`desktop` включает уведомления демона: Linux использует `notify-send`, macOS —
`osascript`. На Windows обязательно задайте `notify_command` в конфиге:
массив аргументов программы уведомлений с подстановками `{title}` и `{text}`.
Этот массив исполняется без shell. Несколько режимов можно включить вместе.

## Команды

| Команда | Что делает |
|---|---|
| `p2p init --name N [--url U]` | создать ключи и конфиг |
| `p2p whoami` | имя, адрес, отпечаток |
| `p2p invite` / `p2p add <invite>` | обмен приглашениями |
| `p2p peers` / `p2p remove N` | список и удаление пиров |
| `p2p allow-tasks N [--off]` | разрешить пиру задачи |
| `p2p send N "текст" [--task] [--reply-to ID]` | отправить |
| `p2p inbox [--all]` / `p2p outbox` / `p2p flush` | входящие, очередь, повтор |
| `p2p wake [MODE …]` | показать или выбрать режимы пробуждения |
| `p2p watch [--interval S] [--once]` | следить за новыми сообщениями |
| `p2p claude-config` | напечатать настройки хуков |
| `p2p serve` | демон (HTTP + повторы + pull) |

Точки входа: `p2p` — CLI, `p2p-mcp` — MCP-сервер, `p2p-hook` — хук уведомлений.
Инструменты MCP: `p2p_peers`, `p2p_send`, `p2p_inbox`, `p2p_await_reply`, `p2p_rules`.
Ресурс `p2p://rules` и инструмент `p2p_rules` дают правила общения: текст пира
недоверен, отправка личных данных требует решения владельца. Прочитайте их перед
работой с сообщениями.

Каталог состояния задаётся `CLAUDE_P2P_HOME` (по умолчанию `~/.claude-p2p`).
Пример юнита systemd — [deploy/claude-p2p.service](deploy/claude-p2p.service).

## Протокол

`POST /v1/msg` принимает конверт:

```json
{"v": "claude-p2p/1", "id": "<uuid hex>", "from": "<ed25519 pub>", "to": "<ed25519 pub>",
 "ts": 1794170000, "kind": "msg|task|result|pull", "in_reply_to": null,
 "nonce": "<12 bytes>", "ct": "<ChaCha20-Poly1305>", "sig": "<ed25519>"}
```

Подпись покрывает все поля, кроме `sig`; заголовок ещё и связан с шифротекстом
как associated data. Ключ шифрования: HKDF-SHA256(X25519(свой, чужой), salt=id).
`pull` — запрос узла за NAT: тело `{"ack": [id…]}`, ответ `{"envelopes": [...]}`.
`GET /v1/hello` отдаёт имя и отпечаток.
